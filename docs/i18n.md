# Internationalization (i18n) Guide

This document describes the i18n system for the Phlix console client and explains how to convert remaining screens.

## Overview

The console client uses SugarCraft's `SugarCraft\Core\I18n\T` translation system, wrapped by `Phlix\Console\I18n\Lang`. All user-facing strings should be routed through `Lang::t()` or `Lang::_()` so they can be translated to other languages.

## Translation Catalog

- **Location**: `resources/lang/`
- **Format**: PHP files returning a `array<string, string>` keyed by dot-separated names (e.g., `'recommendations.title'`)
- **Default locale**: `en.php` (English)

## How to Use

### Basic translation

```php
use Phlix\Console\I18n\Lang;

// Simple key lookup
Lang::t('recommendations.title');  // => "For You"

// With interpolation (uses {name} placeholders)
Lang::t('detail.more_cast', ['count' => 5]);  // => "  +5 more"

// Shorthand alias
Lang::_('recommendations.hint');  // => "Q: Back  ↑↓: Navigate  Enter: Open  X: Dismiss"
```

### Placeholder syntax

Translation values use `{name}` placeholders:

```php
// In resources/lang/en.php:
'detail.more_cast' => '  +{count} more',

// In code:
Lang::t('detail.more_cast', ['count' => $remaining]);
```

### Locale detection

Locale is automatically detected from environment variables (`$LANG`, `$LC_ALL`, `$LC_MESSAGES`) at app boot in `App::boot()`. To override:

```php
use SugarCraft\Core\I18n\T;

T::setLocale('fr');
```

## Converting a Screen

### Step 1: Add the import

```php
use Phlix\Console\I18n\Lang;
```

### Step 2: Identify user-facing strings

Look for:
- Hardcoded strings in `view()` methods
- Strings used in `Chrome::frame()` calls
- Error messages shown to users
- Menu options, hints, and labels

### Step 3: Add keys to the catalog

Add entries to `resources/lang/en.php`:

```php
return [
    // ... existing keys ...

    // ---- YourScreen ------------------------------------
    'yourscreen.title' => 'Your Title',
    'yourscreen.hint' => '↑↓  navigate      Enter  select      Esc  back',
    // ... etc
];
```

### Step 4: Replace hardcoded strings

Replace hardcoded strings with `Lang::t()` calls:

```php
// Before:
return Chrome::frame('Settings', $body, 'Enter  save      Esc  cancel', ...);

// After:
return Chrome::frame(Lang::t('settings.title'), $body, Lang::t('settings.hint'), ...);
```

### Step 5: For dynamic values

Use interpolation:

```php
// In catalog:
'yourscreen.count_items' => '{count} items found',

// In code:
Lang::t('yourscreen.count_items', ['count' => $itemCount]);
```


## Adding a New Locale

To add a new locale (e.g., French):

1. Create `resources/lang/fr.php`:
```php
<?php
return [
    'recommendations.title' => 'Pour vous',
    // ... copy all keys from en.php and translate values
];
```

2. The locale will be auto-detected from `$LANG` environment variable.

## Notes

- Technical values (sort field names like `'name'`, `'year'`; order values `'asc'`, `'desc'`) are NOT translated as they are internal API values. Only their display labels are translated.
- The translation system falls back to the key itself if a translation is missing, so no string is ever lost.
- Tests run against the English catalog by default.
