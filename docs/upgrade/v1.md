# Upgrade Guide

## Upgrading to v1.x (Phase C7/C8)

This guide documents breaking changes and migration steps from pre-C7 versions.

### Configuration Changes

#### TokenStore::exists() Behavior Change

**Before:** `TokenStore::exists()` checked file presence on disk with a plain
`is_file()`. Because a logout leaves an empty token file behind at
`Config::dir()/token.json`, the check stayed `true` after logging out.

**After:** `TokenStore::exists()` is cache-backed. It loads the token file
once, keeps only bundles that carry a non-empty access token, and reports
whether any remain — so an empty or invalid file now correctly returns
`false`.

Treat `exists()` as "is a usable token stored?", not "is the file on disk?",
and not "is the token fresh?" — it does not consult expiry
(`TokenBundle::isExpired()` is the expiry-aware check). `TokenStore` ships no
dedicated file-presence method; if you still need the raw file check, apply
PHP's `is_file()` to the public path from `TokenStore::path()`:

```php
$store = TokenStore::default();
$filePresent = is_file($store->path());
```

#### Config and Token File Formats (migrated automatically)

**Before (pre-C7):** a single server per install — `config.json` carried a
flat `server_url` key, and `token.json` held one flat token bundle.

**After (v1):** `config.json` carries a `servers` array plus an
`active_server_id`, and `token.json` keys its bundles per server under
`by_server`.

No migration steps are required for users upgrading from previous versions:
`Config::load()` converts the legacy single-server config on read, and
`TokenStore` adopts a legacy flat bundle under the reserved `legacy` server
id. Both legacy shapes keep working; each file is rewritten in the new shape
the next time it is saved.

### New Dependencies

- **PHP CodeSniffer (PSR-12):** The project now enforces PSR-12 coding standard.
  If you have custom code, ensure it complies before upgrading.

### New Features Not Requiring Migration

The following new features are available but do not require any special upgrade
steps:

- User sign-up (`/auth/signup`)
- User settings sync with server
- Video file downloads
- Playlists and collections
- External subtitle search
- Shuffle play
- Most-watched rail
- More Like This recommendations
- Missing episodes row on detail screen
- i18n scaffolding (partial — see `docs/i18n.md`)

### CLI Commands

v1 ships these commands: `doctor`, `frame`, `poster`, `run`, `watch`, `version`, `help`.
The `-V` and `--version` flags alias `version`. An unknown command prints
"Unknown command" on stderr and exits 2.

Browse and Search are in-app screens opened with their keyboard keys —
they are not, and never were, CLI verbs. The backward-compatibility guarantee
of v1 lives in the data files, not in a frozen command surface: the legacy
config and token shapes above migrate automatically. The `TokenStore::exists()`
semantics change is the one shipped behavior break this guide documents.
