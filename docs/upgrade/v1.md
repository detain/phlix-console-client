# Upgrade Guide

## Upgrading to v1.x (Phase C7/C8)

This guide documents breaking changes and migration steps from pre-C7 versions.

### Configuration Changes

#### TokenStore::exists() Behavior Change

**Before:** `TokenStore::exists()` checked file presence on disk.

**After:** `TokenStore::exists()` now checks the cache first.

If you have code that relies on the file existence check, you may need to update
your logic to explicitly call `TokenStore::fileExists()` if you still need the
file-based check.

#### Config Migration Data Format

**Before:** Migration data was stored using `var_export` format.

**After:** Migration data is now stored as a PHP array, allowing `load()` to
read it back directly.

This is a internal change only — no migration steps are required for users
upgrading from previous versions.

### New Dependencies

- **PHP CodeSniffer (PSR-12):** The project now enforces PSR-12 coding standard.
  If you have custom code, ensure it complies before upgrading.

### New Features Not Requiring Migration

The following new features are available but do not require any special upgrade
steps:

- User sign-up (`/auth/signup`)
- User settings sync with server
- Video file downloads
- Playlists and collections
- External subtitle search
- Shuffle play
- Most-watched rail
- More Like This recommendations
- Missing episodes row on detail screen
- i18n scaffolding (partial — see `docs/i18n.md`)

### No Breaking API Changes

The CLI commands and their interfaces remain backward compatible. Existing
workflows using `run`, `browse`, `search`, and other commands will continue to
work without modification.
